# Agent guidance for formal-verification-lab

This is an independent, read-only evaluator. Never add GitHub/provider write credentials, Soodles task dispatch, PR merge, runtime admission, or a replacement Test Manager. The producer is not allowed to edit the independent oracle to manufacture PASS.

Read `docs/DECISIONS.md`, `docs/ACCEPTANCE.md`, `docs/SECURITY.md` before changing core semantics. Treat source claims and implementation observations separately. Unknown external effects remain unknown. All public fixtures must be synthetic. No private Soodles content may be committed.

The checker can prove only the formal specification under declared assumptions and bounds. No model check, unit test or synthetic result is production acceptance. The current Session makes engineering judgments and may implement changes within the user-authorized scope. Producer/Provider names identify evidence subjects and effect responsibilities; they are not eligibility gates for discovery, source work, or partial evaluation.

Changes to FVL Properties must come with a named positive/negative/unknown control, counterexample (where meaningful), bound/provenance explanation and actual test result. Fix first broken causal inference; do not add new managers or a second authority. No Lean4 or RLVR runtime dependency in Phase 1.

Partial evidence is a supported input. Check each property's own subject, key, ordering and completeness dependencies. Missing facts make only dependent claims UNKNOWN. Never invent identities, sequences, epochs, grants or effect receipts to make an input fit. A complete private bundle, original Session identity, or external Owner approval is not a blanket prerequisite. No Lab result grants production write or merge authority.
