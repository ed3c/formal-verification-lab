# Repository route interaction

Any repository may use formal-route directly. Its own runner/Test Manager selects
and executes controls; the Lab remains a read-only method and evidence evaluator.
Do not import Soodles, Noodle, an original Owner identity or a complete private
bundle as admission requirements.

P-class describes thinking methods: identify the requirement, challenge the oracle,
separate evidence layers, select a useful method and decide retention from evidence.
Repository `.md` contracts describe actual data/tool paths and return values.
Existing code enforces deterministic identities, selection, transitions and
readback. Prose in a different file is still prose, not an executable state machine.

| Question | Original caller responsibility | Lab interaction |
| --- | --- | --- |
| What behavior is required? | Session reads independent requirement/invariant/compatibility/bug sources. A specification compiler may propose a Scope; it grants no effects. | [Method](FORMAL-ROUTE.md); return genuine new semantic contradictions to the caller's thinking route. |
| Which facts are already known? | Original source/index/registration reader supplies versioned facts and named missing/unsupported scope. | [Mapping quality](SOURCE-MAPPING.md); structure does not decide value. |
| Which controls exist, and how are they classified? | Caller reconciles its actual runner/source denominator and owns its catalog. | [Catalog](TEST-CATALOG.md); labels and CI subsets overlap, request necessity remains separate. |
| Can a control be replaced? | Caller supplies independent contract, valid/fault controls, source/context and actual observations. | [Finite relation](TEST-RETENTION-INTERACTION.md); Session adjudicates meaning and retention. |
| Which controls execute now? | Original Test Manager selects once; original runner executes and retains source/request/results. | No Lab command selects, schedules or runs caller tests. |
| Does new guidance behave correctly? | Installed eval methods, reviewed independent criteria, fresh consumer output/capture and the original feedback owner where available. | Use the method's required behavior evaluation; format PASS is not behavior proof. |

Formal checks are chosen when state/properties need them. A proof/query/property
catalog is not the same denominator as test methods or CI jobs. Model results do
not prove source conformance or unobserved effects. Native, Hook, scheduled work
and delivery remain conditional on their own real event and authorization.

For another repository, record its selected revision, actual runner IDs, source
contracts, necessity conditions, evidence root and original continuation. Use
the existing `catalog`, `mapping` or `retention` commands only for the question
they resolve. Caller-specific identifiers and private traces stay caller-local;
the public Lab contains only portable contracts and synthetic controls.
Missing facts limit dependent claims, never create a new universal gate.
