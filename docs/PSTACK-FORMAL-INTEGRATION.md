## Select an action from the actual gap

| Evidence and need | Formal-route action |
| --- | --- |
| Existing verification and still-applicable evidence cover the requested property | Read the original result and scope. Do not invoke create or maintain and do not claim a fresh PASS. |
| Existing verification lacks a usable project skill | Use create to package the actual runner and evidence. Do not duplicate the model. Verify the generated skill on a real source fault in an isolated fixture. |

| The requirement or Oracle is disputed | Return the specific unresolved premise to the Session's thinking route; continue independent work. |

An input hash, a sync commit and a method name are not complete applicability evidence. Review source, independent expected behavior, model assumptions/bounds, tool/environment facts and relevant dependencies. Retain missing facts. Reuse is scoped historical evidence, not another commit's fresh execution or a replacement for required exact-head acceptance.

## Reconcile upstream reruns with necessary demand

The upstream maintenance procedure begins with a run of the old verification. Perform the applicability review before selecting that procedure. When existing evidence already answers the requested question, consume it and do not invoke maintain. When maintenance is actually required, a new observation can be necessary to distinguish stale verification from a current source fault; preserve its reason, results and cost. Do not describe a skipped procedure as a completed upstream maintenance run.

Creation or changes to the generated skill introduce a distinct execution-path claim. An isolated source mutation verifies that claim even when the underlying proof remains reusable. This does not request an unchanged full suite, an unrelated model query or a Native effect replay. Do not extend a caller's local-software reuse mechanism to solver, Agent or Provider evidence without its own reviewed dependency contract.

## Protect the Oracle before changing expectations

Use the independent user outcome, stable external contract, system invariant or confirmed compatibility requirement that justified the property. Source comments, tests, changelogs and commit messages may locate an intended change; none alone approves a new expected result. Record the old property, proposed property, independent evidence and Session decision before changing it. Preserve failures and rejected proposals. Do not move the sync commit while the property or its source mapping remains unresolved.

A source fault and an Oracle fault need different corrections. A counterexample that is feasible in the actual code is a product finding. An impossible modeled step is a mapping defect. A changed expectation without independent support is an unresolved contract change. Another Agent or a self-generated expected result does not supply independent contract authority.
